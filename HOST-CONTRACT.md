## Steps, in order

1. **Move the tree** — src/ui/ is self-contained: every import is @/ui/…, nothing reaches outside it, and nothing outside it is load-bearing — the generated port-gap list lives at src/ui/data/PORT-ADDITIONS.generated.md for that reason.
   `git mv <nested>/src/ui src/ui`. One directory rename, zero content edits.
2. **Delete the host's src/index.css and its import from src/main.tsx** — It loads normalize.css and blueprint.css unlayered, which silently outranks theme.css and reverts the whole application to stock Blueprint. theme.css is the only global stylesheet. This is the one step whose failure looks like a working app.
   `rm src/index.css`, then remove `import "./index.css"` from src/main.tsx.
3. **Put `// @vitest-environment node` at the top of the host's src/env.test.ts** — This tree needs `environment: "jsdom"` for the whole project. The template's own env.test.ts imports Vite, and therefore esbuild, which throws `new TextEncoder().encode("") instanceof Uint8Array is incorrectly false` inside jsdom. Without the docblock the first tagged release build fails — ci.yml does set VERIFY_ENV_PRODUCTION=true on tagged builds, so the production env check really does run on release.
   Add the docblock as the file's first line. ci.yml is marked DO NOT MODIFY and does not need to change.
4. **Mount App at a single root splat** — See router.why: two routes cause a remount that discards UI state on the first navigation.
   Keep only /auth/callback above App; give App `path: "*"`.
5. **Unbox the mount node** — theme.css owns #root and expects it full bleed and unwrapped.
   Remove the `#root { max-width … }` rule with index.css, and remove the `<div id="root-container">` wrapper from index.html.
6. **Install the dependency delta and set the alias** — The OSDK template ships none of @blueprintjs/icons or the three @fontsource packages, and the tree cannot resolve a single import without the @ alias.
   Install everything in `dependencies` above at those ranges; add `@` → `/src` to vite.config.ts resolve.alias AND tsconfig.json compilerOptions.paths.
7. **Set the vitest block** — The tests render, so they need jsdom; `globals: false` because every test imports from vitest explicitly; `css: false` because assertions are on data-state and never on computed style.
   Copy the `vitest` block above into the host's root vite.config.ts.
8. **Delete the nested harness** — Everything outside src/ui/ in the packet is a local harness the shell replaces. Leaving any of it behind creates the nested app the build cannot reach.
   Delete the nested package.json, package-lock.json, index.html, vite.config.ts, tsconfig.json, eslint.config.js and src/main.tsx. Move scripts/port-additions.mjs to scripts/, and README.md and MANIFEST.md to docs/signatureready/.
9. **Run the suite** — src/ui/host-contract.test.ts asserts every requirement in this file against the host it is now running in. It is the check that the eight steps above actually landed.
   `npm run lint -- --max-warnings 0`, then `npm run test`, then `npm run build`.

## Files that must not exist

- `src/index.css` — THE HIGHEST-RISK ITEM IN THE PORT, because it yields a plausible-looking wrong app rather than an error. The OSDK template's src/index.css imports normalize.css and blueprint.css UNLAYERED. theme.css deliberately puts those same two in @layer vendor so its own unlayered rules outrank them; a second unlayered copy loading afterwards wins every specificity tie, and buttons, cards, dialogs, tables and selects silently revert to stock Blueprint. Stripping the #root rule is not enough — the file has to go, along with its import from main.tsx. theme.css is the only global stylesheet.
- `src/ui/package.json` — No nested app. A prior attempt carried one and the Foundry build never reached the tree: tsconfig includes src only, and Vite's entry is the root index.html.
- `src/ui/index.html` — No nested app. See above.
- `src/ui/vite.config.ts` — No nested app. Vitest's config lives in the host's root vite.config.ts.
- `src/ui/tsconfig.json` — No nested app. One tsconfig, at the root.
- `src/ui/main.tsx` — The mount is shell-owned: it supplies the OSDK provider, the /auth/callback route and the dev-server basename. Nothing under src/ui/ mounts anything.

## The router

The shell mounts App at a SINGLE ROOT SPLAT, which also matches "/". Mounting it at both "/" and "*" — as an earlier version of this contract said — produces a React Router warning and a real defect: with an exact "/" route above the descendant <Routes>, App unmounts and remounts on the first navigation away from the inbox, discarding UI state such as the open sections pane, and flashing. Only /auth/callback belongs above App.

App must also tolerate a non-"/" basename: the Code Workspaces preview serves under a long proxy prefix. So nothing in this tree routes off window.location.pathname and nothing hardcodes an absolute asset path.

```
createBrowserRouter([
  { path: "/auth/callback", element: <AuthCallback /> },
  { path: "*", element: <App /> }
])
```
